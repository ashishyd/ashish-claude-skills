# Build the harness-side checks nobody ships

The strongest unbuilt opportunities are not more prompt-only methodology skills but **deterministic, harness-side tools that run real commands and use Claude Code's newer hook events**. Ranked by evidence of pain, gap size and fit with your existing portfolio: (1) a **vendor-neutral CI failure and flaky-test triager**, (2) a **compaction-continuity plugin** that snapshots goals before compaction and re-injects them after, (3) a **pre-review "reviewer brief" and PR-splitter** aimed at the AI-era review bottleneck, (4) a **migration safety gate backed by a real linter**, and (5) a **cross-session edit log** that warns when parallel sessions touch the same files. Planning, interview, TDD, generic code review, frontend taste, commit/PR and generic security review are saturated and should be avoided ([skills.sh](https://www.skills.sh/)). Every gap area that looks "covered" is in fact covered either by a SaaS-locked vendor skill (Datadog, Develocity, LaunchDarkly) or by a prose checklist with no scripts behind it, which is exactly where an opinionated, tool-agnostic plugin wins. Adoption evidence says ship small, readable, zero-dependency plugins with few sharply described skills, optional hooks and pinned versions. The main uncertainty: two of the hook ideas (affected-test runner, harness-written turn receipt) may overlap your quality-gates and dev-loop, so check those before building.

## Non-coding friction and the review bottleneck are where the hours go

Developers code only about **16% of their time**, and **50% lose 10+ hours a week** to non-coding inefficiency, led by finding information and context switching ([Atlassian DevEx 2025](https://www.atlassian.com/blog/bitbucket/developer-experience-report-2025)). Tech debt is the top frustration at **62.4%**, followed by build-stack complexity (32.9%), deployment complexity (32.3%) and unreliable tools (31.5%) ([SO Survey 2024](https://survey.stackoverflow.co/2024/professional-developers)). Flaky tests hit **15% of developers daily and 24% weekly** ([TestDino](https://testdino.com/blog/flaky-test-benchmark)); the academic survey puts monthly-or-worse exposure at 59% ([ACM TOSEM](https://dl.acm.org/doi/10.1145/3476105)).

AI agents add their own pains. "Almost right" output is the top AI frustration at **66%** ([SO Survey 2025](https://survey.stackoverflow.co/2025/ai)). Agentic PRs wait **5.3x longer for review pickup** and are 2.6x larger, with only 32.7% accepted versus 84.4% for human PRs ([LinearB](https://linearb.io/resources/ai-code-review-bottleneck), vendor data). Copy/paste now exceeds refactored code, reaching 15.7% in H1 2026 ([GitClear](https://www.gitclear.com/the_ai_code_quality_maintainability_gap)). Users repeatedly report plan constraints vanishing after compaction ([r/ClaudeCode](https://www.reddit.com/r/ClaudeCode/comments/1u1777p/experiment_does_claude_codes_autocompaction_drops/)). The implication: the leverage sits in triage, verification, continuity and pre-review, not in generating more code.

## Five plugins ranked by gap size and evidence

| Rank | Idea | Pain evidence | Current offerings | Mechanics | Main trade-off |
|---|---|---|---|---|---|
| 1 | CI and flake triage | Flaky tests weekly for ~40%; unreliable tools 31.5% | Datadog, Develocity, TestDino (SaaS-locked); generic checklists | Skill + scripts reading `gh run view --log-failed` / GitLab logs; optional `agent` subagent | Log formats vary by CI; start with GitHub Actions only |
| 2 | Compaction continuity | Compaction amnesia threads; issue #101309 | Community CONTEXT.md workarounds | PreCompact snapshot to `${CLAUDE_PLUGIN_DATA}`, PostCompact `additionalContext` | Platform may ship this natively |
| 3 | Reviewer brief + PR splitter | 5.3x review wait, 2.6x larger PRs | Generic code-review skills (saturated) | Skill + `agent` that reconstructs intent, maps diff to spec, proposes split | Must not read as "another code review" |
| 4 | Migration safety gate | Deploy complexity 32.3% | Prose checklists; one HARD-GATE table | PreToolUse on migration files/commands wrapping squawk, strong_migrations or Atlas lint | Per-ORM adapters multiply maintenance |
| 5 | Cross-session edit log | Issues #76727 (25 comments), #104352 | None found | PostToolUse writes shared log; PreToolUse warns on files another session touched | Concurrency on a shared file; warn, never block |

**CI triage ranks first** because the gap is clearest. Datadog's flaky-test skill needs CI Visibility ([datadog/pup](https://github.com/datadog/pup/blob/bb7e81a026dc313246af283ce45a03acf077a1e7/skills/dd-triage-flaky-test/SKILL.md)), Develocity's needs Gradle/Maven build data ([Develocity](https://docs.develocity.ai/2026.3/integrations/agentic-ai/skills/develocity-failure-handler/)), and the generic GitHub triage skill is guidance only ([superset-sh](https://github.com/superset-sh/superset/blob/7ae3dc9b162181506a61fe0dc896836f408e5ccd/plugins/github/skills/ci-triage/SKILL.md)). A tool that pulls the failed log, finds the first error, checks the same test across the last N runs, and classifies flake versus regression versus infra needs only the `gh` CLI. Differentiate by refusing to "launder a flake into a pass" and by emitting a verdict with evidence (run IDs, recurrence count).

**Compaction continuity** is the cheapest high-value build: PreCompact and PostCompact exist ([Hooks reference](https://code.claude.com/docs/en/hooks)) and users are asking for exactly this ([#101309](https://github.com/anthropics/claude-code/issues/101309)). Risk: Anthropic could absorb it. That argues for building it small and fast, not for skipping it.

**The reviewer brief** attacks the bottleneck that community threads keep naming ([r/coding](https://www.reddit.com/r/coding/comments/1rxaht2/ai_made_my_team_write_21_more_code_the_review/); [jdno.dev](https://jdno.dev/rethinking-code-review-for-the-ai-era/)). Position it as output for the *human reviewer*: intent, risky hunks, what tests prove, suggested split points. It pairs naturally with your task-brief and feature-flow, since the spec they produce is the input for a spec-versus-diff check.

**The migration gate** beats existing checklists ([cc-polymath](https://github.com/rand/cc-polymath/blob/baa2df114416570f5e0e2961143d20e3716a2fc8/skills/database/postgres-migrations.md); [midudev review-migration](https://github.com/midudev/autoskills/blob/0cc23ef1dd7f08449b9c7c16ac799232ca8ccc77/packages/autoskills/skills-registry/review-migration/SKILL.md)) only if a linter does the judging. Ship Postgres + squawk first; add ORMs on demand.

**The cross-session log** answers an open issue with 25 comments ([#76727](https://github.com/anthropics/claude-code/issues/76727)) and the edit-log request ([#104352](https://github.com/anthropics/claude-code/issues/104352)). It matters more as people run parallel worktree sessions.

## Second-tier ideas worth a smaller bet

A **generic repo env doctor** that reads `.tool-versions`, `.nvmrc`, `engines`, `pyproject` and docker-compose and diffs them against the machine fills a gap: existing doctors are per-product, and the generic one lists tool versions without reading repo requirements ([oaustegard check-tools](https://github.com/oaustegard/claude-skills/blob/62bff7897710d205094a790be55e726ed5832c29/check-tools/SKILL.md)). Evidence of pain is weaker (no survey number on setup time), so it is a quick skill, not a flagship.

**Code-level API contract drift** (server routes versus client call sites in TS, Python or Go) is thin: spec-versus-spec tools wrap oasdiff, and the only code-level example is .NET to TS ([awesome-copilot](https://github.com/github/awesome-copilot/blob/8ecd5b17f02fe5fbebf35eccd1867265eded811f/skills/api-breaking-change-detector/SKILL.md)). High value in polyglot monorepos, but static matching of call sites is hard and false positives will kill trust.

**Vendor-neutral feature-flag cleanup** for home-grown or OpenFeature flags: vendors only cover their own SDKs, and PostHog's skill notes no skill archives a flag yet ([PostHog](https://github.com/posthog/posthog/blob/f1221e34627ac5968bb1d5ac245c92e18d0fa8e6/products/feature_flags/skills/cleaning-up-stale-feature-flags/SKILL.md)). Narrow audience.

**Tool-output trimming** via PostToolUse `updatedToolOutput` (collapse passing test lines, dedupe log noise) is a direct context-cost reducer that only a hook can do ([Hooks reference](https://code.claude.com/docs/en/hooks)); one user cut spend from $1,389 to $200 a month by fixing setup ([Product Compass](https://www.productcompass.pm/p/stop-hitting-claude-code-limits)). Agent **spend attributed to PR or task** is the unsolved part of cost tracking ([PointFive](https://www.pointfive.co/blog/how-to-track-coding-agent-spend-across-your-team)), but personal dashboards are covered by ccusage ([GitHub](https://github.com/ccusage/ccusage)); only build attribution.

Ideas to **skip as duplicates** of your portfolio: a plugin inspector (plugin-audit), a model/effort router (switchboard), a framework upgrade assistant (crowded, and adjacent to dependency-versions). A pre-install **registry-existence check** against hallucinated packages is well justified, since 19.7% of LLM code samples referenced a non-existent package ([CSA](https://labs.cloudsecurityalliance.org/wp-content/uploads/2026/04/CSA_research_note_slopsquatting-ai-supply-chain_20260419-csa-styled-1.pdf)), but it belongs as a PreToolUse hook inside dependency-versions rather than as a new plugin. Likewise, the **affected-test runner** on PostToolBatch ([#101251](https://github.com/anthropics/claude-code/issues/101251)) and the **harness-written turn receipt** that blocks Stop when claims and evidence diverge ([#101247](https://github.com/anthropics/claude-code/issues/101247)) are strong ideas, but they may overlap quality-gates and dev-loop; fold them in there if so.

## Adoption rewards small, readable, hook-optional plugins

The breakout hits are tiny and readable: the Karpathy guidelines repo is one CLAUDE.md with four rules and zero dependencies, now **210k+ stars** ([Firecrawl](https://www.firecrawl.dev/blog/best-claude-code-skills)); frontend-design reached 277K+ installs as a single skill ([Composio](https://composio.dev/content/top-claude-skills)). Readability is also the answer to supply-chain fear: Snyk found prompt injection in **36% of scanned skills** ([Snyk](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub/)), and plugin updates load new code under the original trust ([#73914](https://github.com/anthropics/claude-code/issues/73914)).

Concrete design rules follow from the mechanics. Skill triggering depends entirely on the description, truncated at 1,536 characters inside a listing budget of about 1% of context, and the **least-invoked skills' descriptions are dropped first** ([Skills docs](https://code.claude.com/docs/en/skills)), so ship one to three skills per plugin with "Use when..." first, and use `paths` or `disable-model-invocation` to curb mis-triggers. Users cannot disable a single plugin's hooks ([#57877](https://github.com/anthropics/claude-code/issues/57877)), so declare every hook in the README and gate each with a `userConfig` toggle. Keep state in `${CLAUDE_PLUGIN_DATA}`, avoid `bin/` because claude.ai and Cowork refuse plugins that ship it, and pin `version` ([Plugin reference](https://code.claude.com/docs/en/plugins-reference)). Hooks must be fast, fail open and decode stdin as UTF-8 for Windows ([#96285](https://github.com/anthropics/claude-code/issues/96285)). For reach, write to the SKILL.md standard, which skills.sh distributes to Claude Code, Cursor, Codex, Copilot and others ([skills.sh](https://www.skills.sh/)), and list in Anthropic's community marketplace; reserve plugin packaging for ideas that need hooks.

Trade-off on packaging: one umbrella plugin (for example "ci-and-review") gives one install and shared state, but risks description drop-off and all-or-nothing hooks. Separate small plugins match the adoption evidence. I would ship separate plugins and group them in your existing marketplace.

## Conclusion

The ecosystem has over-invested in telling the model how to think and under-invested in making the harness check what the model did. Your portfolio already leans that way (quality-gates, plugin-audit), so the coherent next move is CI triage plus compaction continuity: both are a week-scale build, both use capabilities prompt-only skills cannot, and neither has a vendor-neutral competitor. The durable risk is platform absorption; Anthropic is visibly closing hook-request issues, so favour ideas tied to external systems (CI, databases, PR review) that the platform is unlikely to build, and treat pure harness features as fast, disposable wins.

What remains unknown: no install data exists per marketplace plugin, "under-used hook events" is inferred from issues rather than measured, and incident triage, perf regression, ownership and license compliance were not researched, so their absence here is not evidence they are saturated.
